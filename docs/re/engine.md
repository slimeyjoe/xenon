# AGS.EXE — engine architecture, boot, main loop, disks, UI

This document covers the engine core: binary layout, boot sequence, the title/omake flow, the
script run loop, the disk/file layer, the message printer, menus, the in-game system menu and error
reporting. Subsystems have their own documents (see [README.md](README.md)).

Conventions: addresses are `SEG:OFF` relative to load base 0 (file offset = `0xE00 + SEG*16 + OFF`;
Ghidra shows `(SEG+0x1000):OFF`). `DS:xxxx` = DGROUP (segment `0F9F`). **verified** = read in code
and/or checked on data; **inferred** = strong evidence, not proven.

## 2. Boot sequence

### 2.1 Hard-disk install (`XENON.BAT` / `AUTOEXEC.BAT`, **verified**)

```
pmd /m10 /v0 /e4 /F /k      ; make PMD (music driver) resident
ags                          ; run the engine with no argument  -> HDD mode
pmd /r > nul                 ; remove PMD
```

`HDINST.BAT <source FDD> <destination HDD>` (its usage text is `hdinst c: a:` — on a PC-98 booted from
the hard disk the HDD is `A:` and the floppy drives follow) creates `\xenon` on the destination drive,
copies `HDINST2.BAT` there, which then asks for disks A–E in turn,
checks each with the marker file `XEN_x.DAT` before copying `*.*`, and verifies `XEN_x_E.DAT` after
the copy. The markers are 7-byte files `"a_disk\x1A"` … `"e_disk\x1A"` (**verified**); the engine
itself never reads them.

### 2.2 Floppy boot (disk A, **verified**)

Disk A is bootable with a minimal third-party DOS (`IO98.SYS`, `MEGDOS.SYS`). Its `CONFIG.SYS` is
`files=10 / buffers=40 / shell=startup.com`. `STARTUP.COM` (355 bytes) is the shell:

1. installs an `INT DCh` handler that returns `AX=FFFFh` when `CL=12h` (the PC-98 MS-DOS "get
   product number" call) — the engine uses this to recognise MEGDOS (§5.1);
2. shrinks itself (`INT 21h/4Ah`), `EXEC \PMD.COM /K /M10 /V0 /F`;
3. `EXEC \AGS.EXE F` → **floppy mode**;
4. prints 「お疲れさまでした。ディスクを抜いて電源をお切りください。」 and halts (`jmp $`).

The floppy set is five 2HD disks with volume labels `_ADISK_` … `_EDISK_`. The engine is always on
disk A in drive 1; data disks B–E go into drive 2 and are requested by script opcode 0x1D (§5.3).
Which file lives on which disk is listed in `resources/inventory.tsv`.

### 2.3 `main()` — 0450:0005 (**verified**)

```c
int main(int argc, char **argv) {
    if (argc == 2 && (argv[1][0] == 'F' || argv[1][0] == 'f')) g_floppy_mode = 1;  /* DS:0074 */
    else if (argc == 1)                                          g_hdd_mode    = 1;  /* DS:0072 */
    else { fprintf(stderr, "オプションが間違っています"); exit(1); }
    engine_init();      /* 0E1A:007F */
    game_main();        /* 0ABA:01DC */
    engine_shutdown();  /* 0E1A:011C */
}
```

Only the first character of the argument is checked. With neither flag set (impossible from
`main`), disk-change requests would be silently skipped.

### 2.4 `engine_init()` — 0E1A:007F (**verified** call order; callee semantics per subsystem docs)

1. `graph_off` 0DCA:00D9 (INT 18h AH=41h)
2. `check_free_memory()` 0E1A:0001: `coreleft()` (0000:16C2, a thunk to `farcoreleft` 0000:2018) `< 0x6C278` (443 000 bytes) → prints
   「メモリ確保に失敗しました」 (DS:09D4), then 「約550KBytes程度の空きメモリが必要です。」 (DS:09ED), and `exit(1)`. The message says 550 KB, the actual
   threshold is ~433 KB of *remaining* far heap after the 72 KB image + DGROUP + stack are loaded.
3. `_setcursortype(0)` 0000:2779 (`ESC[>5h`, hide the text cursor), `fnkey_line_off` 0000:2953 (`ESC[>1h`, hide the function-key row) (platform.md §2.1)
4. `video_init` 0DCA:0041, text-layer clear `0B7D:0A27`, `bios500_set_bit5` 0AF8:0086, `kbd_hook_copy_stop` 0AF8:0022 (INT 05h/06h → null ISR)
5. ANK glyph cache `font_ank_cache_init` 0F16:0009 (font.md §3.1), text-layer clear again
6. `set_access_page(1)`, `gvram_clear`, `set_access_page(0)`, `gvram_clear` (clear both VRAM pages),
   `set_display_page(0)`, `graph_on`
7. `gaiji_define(DS, 09B2h, 7621h)` 0F16:0841: INT 18h AH=1Ah defines user character JIS 7621h = SJIS EB9Fh, the "return key" glyph of the page-overflow prompt (font.md §4)
8. `text_gdc_csrform` 0B7D:09A5 (text-cursor form, argument ignored), `mouse_init` 0E9B:000F (INT 15h mouse hook — platform.md §3.4)
9. `0B2C:006F(1)` sound-effect init: opens `XEN_SE.EFC` (see sound.md)
10. `0C2A:000E` graphics buffer allocation (error 「メモリ確保に失敗しました」 + `da_data..`)
11. text-layer clear

`0E1A:0041` — a check of the BIOS work byte `0000:054D & 0x20` printing 「DIP SW 2-8 を OFF
にして下さい。」/「GDC クロックが 5MHz での動作は保証されません。」 — exists but has **no caller**
(dead code, **verified** by the cross-reference table).

### 2.5 `engine_shutdown()` — 0E1A:011C (**verified** order)

Screen off (`graph_off`), free graphics buffers (`gfx_free_buffers` 0C2A:009B), free the ADT (`adt_free`
0ED8:0217) and stop the blink animator (`blink_stop` 0ED8:03CB, removes the VSYNC hook), stop SE and music
(`se_stop` 0B2C:0461, `music_stop` 0B2C:033C), unhook the mouse (`mouse_shutdown` 0E9B:005D),
`text_gdc_csrform` 0B7D:09A5(0), clear both VRAM pages, restore INT 05h/06h and BIOS byte 0500h
(`kbd_unhook_copy_stop` 0AF8:0061, `bios500_restore` 0AF8:00A2), `_setcursortype(1)` / `fnkey_line_on`
(text cursor and function-key row back on), `graph_on`. PMD stays resident (XENON.BAT removes it).

## 3. Title screen, omake, run loop — `game_main()` 0ABA:01DC (**verified**)

```
logo()                                   ; 0E31:03FA  ROGO.GDT + palette fade (§4)
wait_vsync(0x78)                         ; 0DCA:0012, 120 vsyncs (~2.1 s at 56.4 Hz)
loop:
    reset screen, stop animation (0ED8:03CB), stop music (0B2C:0427, 0B2C:0461), clear pages
    g_progress = first byte of XEN.GDT   ; fopen("xen.gdt","rb"), fread 1 byte into a local pre-set from DS:06FD (0);
                                         ; missing file -> g_progress keeps its previous value (0 at start)
    stop music; show MENU1.GDT (0C2A:0315 + 0C2A:0649); fade in (`pal_fade_to` 0DCA:02F7 with the GDT palette DS:13EC)
    sel = title_menu_select()            ; 0ABA:0190: 3 rows, keys up/down (1/2), 5 = select
    sel 0 "start":  script = !(p&1) ? "s00" : (!(p&2) || !(p&0x3C)) ? "s00b" : "s00c"
    sel 1 "load":   script = "l"         ; L.CC (load menu script)
    sel 2 "omake":  omake_menu() 0ABA:00F5 shows MENU2.GDT, 2 rows:
                      0 -> "k" (K.CC, CG gallery)   only if (p & 0x7F) == 0x7F
                      1 -> "m" (M.CC, music mode)   only if (p & 0x7F) == 0x7F
                      locked -> 「ゲーム終了後にお楽しみ下さい」 (enjoy after finishing the game)
                     -1 (cancel) -> redraw MENU1, back to the title menu
    pal_fade_black(1) (0ABA:038D — palette only, the graphics display stays ON: L.CC relies on it,
    it just does PALETTE 15,15,15,15 and draws its menu, no GRAPH_ON); g_gfx_state[0] = 0; gvram_clear;
    flags_clear_all 088D:1258; g_leave_script (DS:13A6) = 0, DS:13AA = 0 (write-only)
    while (!g_leave_script && !g_quit_game):
        if (!script_load(g_cur_script)) break     ; 088D:0000 ("<name>.cc")
        script_run()                               ; 088D:029A
        script_unload()                            ; 088D:030E
    if (!g_quit_game) goto loop
```

`g_progress` (DS:06E8) is the **XEN.GDT** byte — despite the extension it is a 1-byte progress
bitmask, not an image (**verified**: shipped HDD copy = `00`, the original owner's floppy A = `63h`).
Bits are set by script opcode 0x37 `<int n>` → `XEN.GDT |= 1 << (n-1)`, n = 1..7 (088D:1C19,
re-reads the file, ORs, rewrites with "wb"). Which script sets which bit is listed in
script-catalog.md. The title uses bit 0 (prologue already seen → `S00B`), bit 1 together with any of
bits 2–5 (→ `S00C`), and all seven bits (omake unlocked).

Scripts switch to other files themselves (opcode 0x07 "jump to file" rewrites `g_cur_script` and
ends the current run), so the run loop above is also the chapter-to-chapter driver.

## 4. Built-in sequences (seg 0E31, **verified**)

Three canned sequences are hard-coded in segment 0E31; they are not scripts. Times are in VSYNC
frames (`wait_vsync`, 0DCA:0012; ≈56.4 Hz, ≈17.7 ms each — platform.md §4.1); holding CTRL skips
every wait and makes every fade instant. `pal_fade_to(p, d)` takes at most 16 steps of `d` frames,
`pal_fade_black/white(d)` at most 15; `d = 0` is an immediate palette change (0DCA:02F7).

Helpers (near, all copy from the off-screen plane buffers `g_gfxbuf` DS:13DC to the VRAM plane
segments A800h/B000h/B800h/E000h of the current access page; `off` = `y*80 + x_bytes`):

| Address | Name | Behaviour |
|---|---|---|
| 0E31:000E | `seq_fmemcpy` | `(far dst, far src, n)` rep movsw/movsb |
| 0E31:002D | `seq_slide_up_iplane` | `(off, w, h, step, full)`: for k = 0, step, … ≤ h: copy buffer rows 0..k of plane 3 (intensity) only to VRAM rows h−1−k … h−1 of the rect, then `wait_vsync(1)` — the top of the image rises from the bottom edge of the rect, intensity plane only. If `full == 1` the whole rect (4 planes) is copied afterwards |
| 0E31:0110 | `seq_slide_up` | `(off, w, h, step)`: the same rising reveal with all four planes, k < h |
| 0E31:01D5 | `logo_show_mark` | work palette = `g_gdt_palette` with entries 5–7, 9, 10 set to (0,0,0); `pal_fade_black(0)`; copy rect off 17h (x 184 px, y 0), 17 bytes × 249 lines; `pal_fade_to(work, 6)` |
| 0E31:02E0 | `logo_flash_white` | `pal_fade_to(g_gdt_palette with 5–7, 9, 10 = (15,15,15), 1)`, then `pal_fade_to(g_gdt_palette, 1)` |

## 5. Disk and file layer (seg 0843)

### 5.1 Drive → DA/UA mapping — `drive_to_daua(letter)` 0843:0000 (**verified**)

PC-98 BIOS disk calls (`INT 1Bh`) need a DA/UA byte. The function asks DOS through `INT DCh CL=12h`
(product number):

* result `0` (old DOS): read the DOS work area at `0060:(letter+2Bh)`;
* result `FFFFh` (MEGDOS via STARTUP.COM's hook): fixed map `A..D → 90h..93h` (1 MB FDD units 0–3);
* otherwise: `INT DCh CL=13h` (drive/DA-UA list) and take byte `letter*2+1Bh` of the returned table.

Values outside `70h..A7h` or with bits `0Ch` set are rejected (returns 0). For SCSI units (DA/UA ≥ A0h) the
unit must also answer `INT 1Bh AH=84h` (sense) without carry, else 0.

### 5.2 Opening files — `xfopen(name, mode)` 0843:0384 (**verified**)

1. if the current drive is ready (`cur_drive_ready` 0843:032A → `disk_sense`), `fopen(name, mode)`;
2. otherwise / on failure, `find_file_any_drive` 0843:01B2 walks every DOS drive (count from
   `INT 21h/52h`), skips FDD units that sense as not ready (`INT 1Bh AH=04h`, status `60h`), and
   `findfirst("X:name", FA_RDONLY|FA_ARCH)`; the first hit is opened as `"X:name"`.

So every asset is found by searching all drives — this is what lets the floppy version work with a
data disk in drive 2 without explicit paths, and lets the HDD version run from any directory that
holds the files.

### 5.3 Disk change — opcode 0x1D, `op_disk_change` 088D:0F9C (**verified**)

Operand: a string whose first character is a full-width letter (e.g. `Ｂ`). It is converted to
half-width (`zentohan` 0000:4502, Japanese RTL) to build `"_BDISK_"`; the label comparison uses
`stricmp` (0000:4237), i.e. it ignores case.

* HDD mode: returns immediately.
* Floppy mode: loop — wait until drive `B:` senses ready (showing 「ディスクをセットして下さい」 via
  `error_box`), read its volume label (`get_volume_label` 0843:0404: `findfirst("B:\_?DISK_", FA_LABEL)`),
  and if it differs, show 「Ｂディスクをドライブ２へ入れて下さい」 on the text layer and wait for a key.

The save loader performs the same check for the label recorded in the save (§ save-format.md).

### 5.4 Error boxes — `error_box(msg)` 088D:13DF (**verified**)

Clears the text layer, screen-off call `0DCA:00D9`, beeps (`sound(500)`, `delay(500)`, `nosound()`),
prints `ESC[7;31m msg ESC[0m` centred on text row 10 (`text_locate((80 − strlen)/2 + 1, 10)`, 1-based: row 9 from 0), waits for a key. Messages that go through it:
「ディスクへ書き込みができません」 (write-protected, sense `10h`), 「ディスクをセットして下さい」,
「ゲームディスクではありません」, 「ディスクが違います」, 「ファイルがオープンできません」.

## 6. Message printer — `text_print(char far *s, int flag)` 0B7D:019B (**verified**)

The interpreter calls it for every `FD` message token as `text_print(str, !kbd_kana_locked())`; the
second argument is passed through unchanged to the full-width glyph routines, which use it as
`wait_vsync(flag)` before each glyph: KANA lock off → one VSYNC per full-width character (typewriter
effect), KANA lock on → instant text (font.md §2.1, **verified**).

The message window is drawn into **graphic** VRAM with the font routines of seg 0F16; only the
page-wait cursor and error messages use the **text** layer (via DOS console escape sequences).

Window geometry (DGROUP, **verified** initial values):

| Global | Value | Meaning |
|---|---|---|
| DS:07D8 | 10 | window left edge in byte columns (×8 px = 80 px) |
| DS:07DA | 313 | window top in pixels |
| DS:07DC | 15 | text (foreground) colour |
| DS:07DE | 0 | background colour of each opaque glyph cell (font.md §2) |
| row pitch | 18 px | `y = 313 + row*18`, 4 rows → y 313..384 |

Algorithm (per byte at `s`):

| Byte(s) | Action |
|---|---|
| Shift-JIS lead byte (Japanese RTL `_mbctype` table DS:0F4C, test `[0F4D+c] & 4`) | draw the 2-byte glyph with `kanji_draw` 0F16:03D7`(x0+col, y0+row*18, DS:07DC, DS:07DE, lead, trail, flag)`; `col += 2` |
| `@` (0x40) | skip it **and the following byte**, print the string at DS:06EA (default `" "`) through `text_print_big`'s path — a name-insertion hook that Xenon never uses (inferred) |
| 0x0A | new row (`col = 0, row++`) |
| 0x0C | wait for a key (`0AF8:0254`) |
| 0x03 … 0x03 | the bytes between two 0x03 are drawn as 32×32 double-size glyphs (`kanji_draw_big` 0F16:051D, always colour 15 on 0, 16 lines above the row), `col += 4` per 2-byte char |
| 0x04 d | `d` must be `'0'..'9'` (else prints 「数字ではない」); end-of-message wait becomes `(d-'0')*60` ticks instead of a key wait |
| 0x05 | do not clear the window after the message |
| any other byte | single-byte (ANK) glyph via `ank_draw` 0F16:06BC (no VSYNC wait; only 20h–7Fh have valid glyphs, font.md §3.1), `col += 1` — this is the path the English patch uses |

Line breaking (after each glyph):

* when `col >= 60`: look at the **next** two bytes. If they are one of the hanging-punctuation
  characters 、。？！）」』 (table 0B7D:046C: 8141, 8142, 8148, 8149, 816A, 8176, 8178) the first time,
  the line is allowed to overflow by that one character (flag `[bp-6]`); a second consecutive hit
  breaks. If the next character is 々 (8158) — which must not start a line — it is **replaced in the
  string by the preceding kanji** and the line breaks (the repetition mark is spelled out).
* independently, a break happens when `x0 + col >= 80` (right edge of the screen).
* when `row` reaches 4: put the blinking page cursor (`ESC[5;37m` + SJIS `EB9Fh` = the engine's user character 7621h, a "return key" symbol defined at start-up (font.md §4), + `ESC[0m`, DS:08B1)
  at `text_locate(73, 24)` = `ESC[24;73H` — **1-based** like every ANSI cursor position, i.e. text cell
  (72, 23) counted from 0, pixels x 576..591 / y 368..383, the bottom-right corner inside the WAKU text
  box — wait for a key, clear the text layer and the window
  (`text_window_clear` 0B7D:0783), continue at row 0.

End of string: if no 0x04 was seen, show the blinking `▼` (DS:08D2) at the same `ESC[24;73H` position, wait for a key
and clear the text layer; otherwise wait the given number of vsyncs (`wait_vsync` 0DCA:0012; holding CTRL skips all waits). Unless 0x05 was seen, clear
the window.

So a page holds 4 × 60 bytes; long strings page automatically; words are **not** wrapped (the
English translation pads with spaces).

`text_print_big` (0B7D:000C) is a reduced copy of the printer used for the `@` insertion: it handles
SJIS, 0x0C and 0x03…0x03, and stalls on any other single byte.

## 7. Choice menus — `select_menu(char far **items, int initial)` 0B7D:048C (**verified**)

* `items` is a NULL-terminated array of far string pointers (built by the script interpreter from
  the menu block, see opcodes.md). No items → 「menu : 選択項目がありません」.
* The option area is cleared (`menu_clear`, width = longest item), each option is drawn with
  `sprintf("%-*s")` + `0F16:07D5` at `x = DS:07E0 (10)`, `y = DS:07E2 (313) + i*18` — i.e. inside the
  message window, one row per option, so at most 4 options fit (**inferred** from geometry; the
  scripts never use more, see script-catalog.md).
* The current row is highlighted by XOR-inverting all four planes over 16 lines (`menu_hilite`).
* Input (`0AF8:00BD` waits for key release, `0AF8:02C7` returns a command code, see platform.md):
  1 = up, 2 = down, 5 = OK → index, 0 = cancel (ESC / right click) → −1, 8 = HELP → −2. The cursor
  wraps around with the keyboard; when the last input came from the mouse (DS:13B6
  `g_input_from_mouse` ≠ 0) it clamps at the ends instead.
* On the way out (OK, cancel or HELP alike) the option rows are wiped again with
  `menu_clear(0x3C, count)` (0B7D:05BB) — over the **full window width** of 60 bytes, not the
  longest item — so nothing of the menu survives into the next page.
* The interpreter treats −1/−2 as "open the system menu" (088D:0A68).

The title and omake menus are separate, simpler loops (`0ABA:0190`, `0ABA:00F5`) that highlight a
fixed bar (`0ABA:0056`: 28 bytes × 32 lines at x = 26 bytes, row table DS:06F7) over the menu graphic.

## 8. In-game system menu — `cc_system_menu()` 088D:223D (**verified**)

Opened when a script choice menu returns −1 or −2 (cancel / HELP):

| Item (DS:021C table) | Effect |
|---|---|
| 　キャンセル　 | back to the choice |
| 　最初に戻る　 | `g_leave_script = 1` → back to the title |
| 　ゲーム終了　 | second menu (DS:022C): 「このままゲームを続ける。」 → back; 「本当にゲームを終了する。」 → `g_leave_script = g_quit_game = 1` → DOS |

There is no save/load in this menu: saving and loading are script opcodes offered at fixed points
(save-format.md, script-catalog.md).
